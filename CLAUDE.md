# fotoflash-frontend

Фронтенд сайта бронирования фотостудии **ФОТОФЛЕШ** (переделка старого сайта `fotoflash.studio` с нуля, дизайн тоже новый). Бэкенд лежит в соседнем репозитории `../fotoflash-backend`: Django + DRF, там же вся бизнес-логика (цены, слоты, оплата, баллы). Фронтенд отвечает за интерфейс и вызывает API.

## Контракт с бэкендом

Источник правды лежит в бэкенде и подтягивается сюда импортом (при первой загрузке Claude Code попросит подтвердить внешний импорт):

@../fotoflash-backend/docs/frontend-contract.md

Что ещё полезно из бэкенда: `../fotoflash-backend/CLAUDE.md` (модель домена, решения, платежи) и OpenAPI-схема `http://localhost:8000/api/schema/` (если расходится с контрактом, прав схема).

Правила взаимодействия двух сессий:
- Бэкенд отсюда не менять. Нужна правка API, поле, эндпоинт или новый документ: записать в `docs/backend-requests.md` (формат внутри). Бэкенд-сессия читает этот файл. Исключение: заполнение данных в локальной базе по прямой просьбе Виктора.
- Поменялся контракт на бэкенде: обновлён `docs/frontend-contract.md`. Перед работой с API перечитать и перегенерировать типы (`npm run gen:api`), не полагаться на память.
- Не изобретать поля и эндпоинты: сверяться с контрактом и схемой.
- После правки `.env` бэкенда его контейнер надо пересоздавать (`docker compose up -d --force-recreate --no-deps web`), обычный restart env не перечитывает.

## Стек и решения

- Next.js 16 (App Router, `cacheComponents`), React 19, TypeScript, Tailwind 4. Пакеты через npm, Node через fnm. Зависимости не добавлять без согласования. Сейчас из «лишнего» только `lucide-react` (иконки) и `openapi-typescript` (dev).
- **Next здесь не такой, как в обучающих данных**: перед правкой роутинга, кеша и конфига читать `node_modules/next/dist/docs/` (см. `AGENTS.md`). В пререндере `new Date()`/`Math.random()` ломают сборку, данные запроса (`params`, `searchParams`) читать внутри `<Suspense>`.
- Фронтенд и API на **одном origin** (сессия в httpOnly-cookie, нужен CSRF). В dev: Next.js на `:3000`, rewrites `/api/*` → `BACKEND_URL` (слэш в конце восстанавливается, `skipTrailingSlashRedirect`). Бэкенд разрешает `http://localhost:3000` в `CSRF_TRUSTED_ORIGINS`.
- Все вызовы API через один модуль-клиент `src/lib/api/client.ts`: `credentials: "include"`, CSRF с одним повтором, разбор `{detail, code}`. Компоненты `fetch` напрямую не вызывают. Типы из OpenAPI: `npm run gen:api` (файл `src/lib/api/schema.d.ts`, лежит в репозитории).
- Серверные компоненты для публичного каталога (залы, допы, документы, студия): `src/lib/api/catalog.ts`, кеш до часа с тегами. Всё про клиента (профиль, брони, оплата) только на клиенте с cookie.
- **Иконки только из `lucide-react`**, инлайн-SVG для иконок не писать (исключение: логотип `LogoMark`).
- Нативные элементы вместо самодельных: `<dialog>`, `input`, `checkbox`, `<details>`, scroll-snap. Сложные инпуты не изобретаем.

## Что сделано

| Маршрут | Что это |
|---|---|
| `/` | Главная: hero с видео и «линзой» за курсором, залы, контакты (блок скрыт, если контактов нет) |
| `/halls` | Каталог залов, bento-сетка (`src/lib/bento.ts`), порядок как в админке (`sort` в API) |
| `/halls/[slug]` | Галерея-карусель, календарь на горизонт (`booking_horizon_days`), часы, итог из `quote` |
| `/booking` | Шаг допов: категории, поиск, сводка, итог. Без параметров ведёт на `/halls` |
| `/booking/checkout` | Состав, баллы, оплата; вход по коду показывается, если нет сессии |
| `/profile` | Кабинет: брони, профиль (имя, телефон), баллы, выход |
| `/profile/bookings/[id]` | Карточка брони, возврат из банка (опрос статуса до 30 с), таймер, отмена |
| `/dev/pay/[id]` | Фейковая оплата, только dev |
| `not-found`, `error` | Своя 404 и страница ошибки |
| `robots`, `sitemap`, `manifest`, иконки, OG | SEO и PWA-минимум |

Намеренно нет: отдельной страницы входа, `/contacts`, страницы оборудования и документов-обёрток, акций, новостей, команды, паролей.

## Как устроено бронирование и вход

- Вход в бронирование только со страницы зала. 3 шага: время (страница зала) → допы (`/booking`) → итог и оплата (`/booking/checkout`). Состояние в URL (`src/lib/booking-params.ts`: `location`, `starts_at`, `ends_at`, `extras=id:часы,...`).
- Вход по email-коду один компонент `LoginPanel`: и в модалке из шапки (`AuthProvider`, `useAuth().openLogin()`), и на шаге оплаты. Порядок: email → код → если `consent_required`, имя и согласие (новый клиент) → если после входа имя пустое, спрашиваем имя (`PATCH /me/`).
- Незаконченная бронь хранится на устройстве (`localStorage`, `src/lib/booking-draft.ts`) и подсвечивается в шапке кнопкой «Бронь» с красным мигающим индикатором. Очищается при оплате, отмене, истечении, прошедшем времени. Готовые `ResumeBooking`/`ResumeBookingCard` пока нигде не стоят.
- Оплата: на checkout уже созданная неоплаченная бронь устройства (черновик с `bookingId`) не создаётся заново: она держит слот, повторный `POST /bookings/` дал бы `409`. Не изменилась: уходим на `/profile/bookings/{id}`. Изменили допы или время: старая отменяется, цена считается заново. Двойной клик защищён `ref`, возврат из bfcache сбрасывает «Переходим…».
- Поле баллов текстовое (только цифры), последний известный `max_bonus_points` и сумма держатся на экране, пока считается новая цена.
- Кеш каталога сбрасывает бэкенд: `POST /revalidate?tag=extras|locations|studio|documents` с `Authorization: Bearer $REVALIDATE_SECRET` (в dev без секрета открыто). В dev, если данные «застряли», достаточно дёрнуть этот адрес.

## Ключевые правила предметной области

- **Название бренда пишем кириллицей и заглавными: ФОТОФЛЕШ** (закон о госязыке). Везде, где текст видит человек: заголовки, мета, логотип, aria-label, alt, комментарии и документация. Латиница только в технических идентификаторах (репозиторий, пакет, домен, slug, CSS-классы). То же правило записано для бэкенда в `docs/backend-requests.md`.
- **Вход только по email-коду** (6 цифр). Новому клиенту нужен чекбокс согласия на обработку ПД со ссылкой на `personal-data-consent`.
- **Расчёт цены делает бэкенд**: показывать `quote` и `price` слотов, самим не считать. Деньги это строки `"3000.00"`, сравнивать числом можно, считать нельзя.
- **Бронь удерживается ограниченное время** (`expires_at`, срок задаёт бэкенд, число в тексте не писать): показать таймер.
- **После возврата из банка `?payment=success` ничего не доказывает**: опрашивать бронь до `confirmed`.
- **Сертификаты Минцифры**: рядом с оплатой и на карточке брони нужна подсказка (Яндекс Браузер / приложение банка / установка сертификатов, ссылку скопировать).
- **Отмена**: `can_cancel` и `cancel_deadline` приходят готовыми.
- Время показывать по времени студии (+05:00, строки API уже в нём), форматировать на русском, склонения через `src/lib/plural.ts`.

## Dev-окружение

1. Поднять бэкенд: `cd ../fotoflash-backend && docker compose up -d` (API `:8000`, письма с кодами в mailpit `:8025`, админка `/admin/`, `admin@example.com` / `admin`).
2. В бэкенде лежат демо-залы, оборудование и брони (`seed_demo`). Контакты, документы-заглушки и категории допов заведены в локальной базе.
3. Платежи в dev фейковые: `payment_url` ведёт на `/dev/pay/fake-{id}`, страница вызывает `simulate`. В продакшн-сборку не попадает.
4. Проверка в живом браузере без зависимостей: `node scripts/cdp-run.mjs <url> <prefix> eval:... shot:...` (headless Chrome через CDP, умеет кликать, вводить код из mailpit, снимать скриншоты).
5. Грабли: при правке токенов `@theme` в `globals.css` (и Tailwind-утилит с новыми переменными) Turbopack dev может отдавать старый CSS, помогает перезапуск `npm run dev`. Кеш `use cache` в dev живёт до часа, сбрасывается `POST /revalidate`.

## Деплой

Готово к первому выпуску, ещё не запускалось. Первый выпуск это тестовый стенд для показа клиенту на личном VPS (не прод). Файлы: `Dockerfile` (Node 22, `output: "standalone"`, `node server.js`), `docker-compose.yml` (Traefik, `mem_limit`, без `www`-роутера: на тестовом поддомене он не нужен, на боевом домене добавить по правилу из глобального CLAUDE.md), `.github/workflows/deploy.yml` (typecheck + lint, сборка в GHCR, SSH). Домен-предложение `fotoflash.zagoruykov.site` (константа `DOMAIN` в workflow), нужна A-запись на 89.111.165.57.

- **Сборка требует живой бэкенд**: каталог пререндерится из API. `BACKEND_URL` и `SITE_URL` передаются build-аргументами (в CI это публичный адрес того же домена). Значит, бэкенд должен быть выпущен раньше фронтенда. Если понадобится сборка без бэкенда, каталог переводится на рендер по запросу (`connection()` и `Suspense` вокруг корневого layout), это отдельная работа.
- **Один домен**: Traefik отдаёт `/api` и `/media` бэкенду (роутер с `PathPrefix` и приоритетом выше), остальное идёт во фронтенд. Rewrites в `next.config.ts` (`/api/v1/*`) нужны только в dev и запекаются при сборке.
- Хост картинок берётся из `BACKEND_URL` и `SITE_URL` (`remotePatterns` строятся в `next.config.ts`).
- Секрет `REVALIDATE_SECRET` добавить в GitHub secrets, бэкенд зовёт `POST /revalidate` с тем же значением.
- Проверено локально: образ собирается, контейнер отдаёт страницы, `/api` через rewrite, `/revalidate` с секретом (401 без него), `/dev/*` 404. Картинки через оптимизатор проверять на реальном домене (на `localhost` Next блокирует приватные IP).
- Пушить только по явной просьбе. Git пока не инициализирован.
